CHƯƠNG 5: LẬP TRÌNH HƯỚNG ĐỐI TƯỢNG (OOP)

Mục tiêu chương

  • Hiểu được tư tưởng của lập trình hướng đối tượng (OOP) và sự khác biệt so với lập trình hướng thủ tục.
  • Phân biệt rõ lớp (class) và đối tượng (object).
  • Biết khai báo lớp, thuộc tính, phương thức, constructor và tạo đối tượng bằng new.
  • Nắm vững bốn tính chất cốt lõi của OOP: Đóng gói, Kế thừa, Đa hình, Trừu tượng.
  • Sử dụng được các từ khóa this, super, static, final, private/protected/public.
  • Hiểu và cài đặt được abstract class và interface.
  • Ghi đè phương thức (@Override) và nạp chồng phương thức (overloading).
  • Vận dụng OOP để mô hình hóa bài toán thực tế đơn giản.

PHẦN LÝ THUYẾT

5.1. Tổng quan về lập trình hướng đối tượng

5.1.1. Vì sao cần OOP?

Lập trình hướng thủ tục (procedural) tổ chức chương trình thành các hàm, dữ liệu và xử lý tách rời nhau. Khi dự án lớn lên, cách này khiến mã khó bảo trì, khó mở rộng và dễ sinh lỗi. Lập trình hướng đối tượng (OOP – Object-Oriented Programming) giải quyết vấn đề đó bằng cách gom dữ liệu và các hành vi liên quan vào cùng một đơn vị gọi là đối tượng.

  • Chương trình = tập hợp các đối tượng tương tác với nhau.
  • Mỗi đối tượng đóng gói trạng thái (thuộc tính) và hành vi (phương thức).
  • Giúp mã nguồn gần với thế giới thực, dễ tái sử dụng và mở rộng.

5.1.2. Bốn tính chất cốt lõi của OOP

Tính chất Ý nghĩa Từ khóa / công cụ
Đóng gói (Encapsulation) Che giấu dữ liệu bên trong, chỉ cho phép truy cập qua phương thức công khai private, getter/setter
Kế thừa (Inheritance) Lớp con dùng lại thuộc tính, phương thức của lớp cha extends
Đa hình (Polymorphism) Cùng một lời gọi phương thức nhưng có nhiều cách thực thi khác nhau Overloading, Overriding
Trừu tượng (Abstraction) Chỉ quan tâm "làm gì", ẩn đi "làm như thế nào" abstract, interface

5.2. Lớp và đối tượng

5.2.1. Khái niệm

Lớp (class) là bản thiết kế (khuôn mẫu) mô tả thuộc tính và hành vi của một tập các đối tượng cùng loại. Đối tượng (object) là một thể hiện (instance) cụ thể của lớp, được tạo ra trong bộ nhớ bằng từ khóa new.

Ví dụ: SinhVien là lớp – còn "Nguyễn Văn A", "Trần Thị B" là các đối tượng cụ thể của lớp đó.

5.2.2. Cú pháp khai báo lớp

[phạm vi truy cập] class TenLop {
    // thuộc tính (fields)
    // constructor
    // phương thức (methods)
}

Ví dụ lớp SinhVien đơn giản:

public class SinhVien {
    String maSV;
    String hoTen;
    int namSinh;

    public void gioiThieu() {
        System.out.println("Toi la " + hoTen + ", MSSV " + maSV);
    }
}

5.2.3. Tạo đối tượng

SinhVien sv1 = new SinhVien();
sv1.maSV = "SV001";
sv1.hoTen = "Nguyễn Văn A";
sv1.namSinh = 2004;
sv1.gioiThieu();  // Toi la Nguyễn Văn A, MSSV SV001

Ghi nhớ: biến đối tượng chỉ lưu tham chiếu tới vùng nhớ trên heap. Nếu chưa gán bằng new, biến có giá trị null.

5.3. Thuộc tính và phương thức

5.3.1. Thuộc tính (field)

Mỗi đối tượng có bản sao riêng của các thuộc tính không phải static.

public class HinhTron {
    double banKinh;
    String mauSac;
}

5.3.2. Phương thức (method)

Cú pháp khai báo phương thức:

[phạm vi] [static] kieuTraVe tenPhuongThuc(danhSachThamSo) {
    // thân phương thức
    // return ...;
}

Ví dụ:

public class HinhTron {
    double banKinh;

    public double dienTich() {
        return Math.PI * banKinh * banKinh;
    }

    public double chuVi() {
        return 2 * Math.PI * banKinh;
    }
}

Phương thức không có giá trị trả về thì dùng void. Phương thức có giá trị trả về phải có return đúng kiểu.

5.4. Constructor – Phương thức khởi tạo

5.4.1. Đặc điểm

  • Trùng tên với lớp.
  • Không có kiểu trả về (kể cả void).
  • Được gọi tự động khi dùng new.
  • Nếu không viết constructor nào, Java tự sinh constructor mặc định không tham số.

5.4.2. Các loại constructor

public class SinhVien {
    String maSV;
    String hoTen;

    // Constructor không tham số
    public SinhVien() {
        this.maSV = "Chua co";
        this.hoTen = "Chua co";
    }

    // Constructor có tham số
    public SinhVien(String maSV, String hoTen) {
        this.maSV = maSV;
        this.hoTen = hoTen;
    }
}

Nạp chồng constructor (constructor overloading): nhiều constructor trong cùng lớp, khác nhau về danh sách tham số.

5.4.3. Từ khóa this

Dùng this để tham chiếu tới chính đối tượng hiện tại:

  • Phân biệt thuộc tính và tham số trùng tên.
  • Gọi constructor khác trong cùng lớp: this(...).
public SinhVien(String maSV) {
    this(maSV, "Chua co");   // gọi constructor 2 tham số
}

5.5. Đóng gói (Encapsulation)

5.5.1. Khái niệm

Đóng gói là che giấu thuộc tính khỏi bên ngoài, chỉ cho phép truy cập thông qua các phương thức công khai (getter / setter). Mục đích: bảo vệ dữ liệu khỏi bị sửa tùy tiện, đảm bảo tính nhất quán.

5.5.2. Phạm vi truy cập (Access Modifier)

Phạm vi Cùng lớp Cùng package Lớp con khác package Ngoài package
private✔✘✘✘
(mặc định)✔✔✘✘
protected✔✔✔✘
public✔✔✔✔

5.5.3. Ví dụ đóng gói

public class TaiKhoan {
    private String soTK;
    private double soDu;

    public TaiKhoan(String soTK, double soDu) {
        this.soTK = soTK;
        this.soDu = soDu;
    }

    // getter
    public double getSoDu() {
        return soDu;
    }

    // setter có kiểm tra
    public void napTien(double soTien) {
        if (soTien > 0) {
            soDu += soTien;
        }
    }

    public void rutTien(double soTien) {
        if (soTien > 0 && soTien <= soDu) {
            soDu -= soTien;
        } else {
            System.out.println("So du khong du!");
        }
    }
}

Nhờ đóng gói, bên ngoài không thể làm taiKhoan.soDu = -100; – việc gán luôn đi qua phương thức có kiểm tra.

5.6. Kế thừa (Inheritance)

5.6.1. Khái niệm

Kế thừa cho phép lớp con (subclass) dùng lại thuộc tính và phương thức của lớp cha (superclass). Java dùng từ khóa extends. Java chỉ hỗ trợ đơn kế thừa (một lớp con chỉ extends một lớp cha).

5.6.2. Cú pháp và ví dụ

// Lớp cha
public class DongVat {
    protected String ten;

    public void an() {
        System.out.println(ten + " dang an...");
    }
}

// Lớp con
public class Cho extends DongVat {
    public void sua() {
        System.out.println(ten + " dang sua: gau gau!");
    }
}

// Sử dụng
Cho c = new Cho();
c.ten = "Milu";
c.an();    // kế thừa từ DongVat
c.sua();   // phương thức riêng của Cho

5.6.3. Từ khóa super

  • super(...) – gọi constructor của lớp cha (phải đặt ở dòng đầu tiên).
  • super.tenPhuongThuc() – gọi phương thức của lớp cha (khi lớp con ghi đè).
  • super.thuocTinh – truy cập thuộc tính của lớp cha.
public class Cho extends DongVat {
    public Cho() {
        super();                // gọi constructor DongVat()
        this.ten = "Milu";
    }

    @Override
    public void an() {
        super.an();             // gọi lại phương thức của lớp cha
        System.out.println("Cho an nhieu hon!");
    }
}

5.6.4. Ghi đè phương thức (@Override)

Lớp con có thể định nghĩa lại phương thức đã có ở lớp cha với cùng tên, cùng tham số, cùng kiểu trả về (hoặc kiểu trả về hẹp hơn). Nên thêm annotation @Override để trình biên dịch kiểm tra.

Lưu ý: không thể ghi đè phương thức final và phương thức static.

5.7. Đa hình (Polymorphism)

5.7.1. Hai loại đa hình

  • Nạp chồng (Overloading) – đa hình tĩnh (compile-time): nhiều phương thức cùng tên, khác danh sách tham số, trong cùng lớp.
  • Ghi đè (Overriding) – đa hình động (runtime): lớp con định nghĩa lại phương thức của lớp cha. Phương thức nào được gọi phụ thuộc vào kiểu thực của đối tượng tại runtime.

5.7.2. Ví dụ Overloading

public class MayTinh {
    public int cong(int a, int b) {
        return a + b;
    }

    public double cong(double a, double b) {
        return a + b;
    }

    public int cong(int a, int b, int c) {
        return a + b + c;
    }
}

5.7.3. Ví dụ Overriding – đa hình runtime

class Hinh {
    public void ve() {
        System.out.println("Ve hinh...");
    }
}

class HinhVuong extends Hinh {
    @Override
    public void ve() {
        System.out.println("Ve hinh vuong");
    }
}

class HinhTron extends Hinh {
    @Override
    public void ve() {
        System.out.println("Ve hinh tron");
    }
}

public class Demo {
    public static void main(String[] args) {
        Hinh[] ds = { new HinhVuong(), new HinhTron() };
        for (Hinh h : ds) {
            h.ve();   // gọi phương thức theo KIỂU THỰC của đối tượng
        }
    }
}

5.8. Trừu tượng (Abstraction)

5.8.1. Lớp trừu tượng – abstract class

  • Khai báo bằng abstract class, không thể tạo đối tượng trực tiếp.
  • Có thể chứa phương thức trừu tượng (chỉ khai báo, không có thân) và phương thức thường.
  • Lớp con phải cài đặt tất cả phương thức trừu tượng (hoặc chính nó cũng abstract).
public abstract class Hinh {
    protected String ten;

    public abstract double dienTich();    // không có thân

    public void inThongTin() {
        System.out.println(ten + " co dien tich = " + dienTich());
    }
}

class HinhChuNhat extends Hinh {
    private double dai, rong;

    public HinhChuNhat(double dai, double rong) {
        this.ten = "HCN";
        this.dai = dai;
        this.rong = rong;
    }

    @Override
    public double dienTich() {
        return dai * rong;
    }
}

5.8.2. Interface

  • Là một "hợp đồng" – chỉ chứa phương thức trừu tượng (mặc định) và hằng số.
  • Khai báo bằng interface, lớp hiện thực bằng implements.
  • Một lớp có thể implements nhiều interface.
  • Từ Java 8 trở đi, interface có thể có default method và static method.
public interface CoTheBay {
    void bay();
}

public interface CoTheBoi {
    void boi();
}

public class VitTroi implements CoTheBay, CoTheBoi {
    @Override
    public void bay() {
        System.out.println("Vit troi bay...");
    }

    @Override
    public void boi() {
        System.out.println("Vit troi boi...");
    }
}

5.9. Từ khóa static và final

5.9.1. static

  • Thuộc tính static: dùng chung cho tất cả đối tượng (không phụ thuộc instance).
  • Phương thức static: gọi trực tiếp qua tên lớp, không cần đối tượng.
  • Khối static: chạy một lần khi lớp được nạp.
public class Dem {
    public static int soLuong = 0;   // dùng chung

    public Dem() {
        soLuong++;                    // mỗi lần new, tăng 1
    }

    public static void inSoLuong() {
        System.out.println("Da tao " + soLuong + " doi tuong");
    }
}

5.9.2. final

  • Biến final: hằng số, không thể gán lại.
  • Phương thức final: không thể bị ghi đè.
  • Lớp final: không thể bị kế thừa.
public final class Constants {
    public static final double PI = 3.14159;
    public static final int MAX_SIZE = 100;
}

5.10. Ví dụ tổng hợp

Chương trình quản lý nhân viên minh họa đầy đủ đóng gói – kế thừa – đa hình – trừu tượng: 

// Lớp trừu tượng
abstract class NhanVien {
    private String maNV;
    private String hoTen;

    public NhanVien(String maNV, String hoTen) {
        this.maNV = maNV;
        this.hoTen = hoTen;
    }

    public String getMaNV() { return maNV; }
    public String getHoTen() { return hoTen; }

    public abstract double tinhLuong();

    public void inThongTin() {
        System.out.printf("%-8s %-20s Luong: %.2f%n",
                maNV, hoTen, tinhLuong());
    }
}

// Lớp con 1
class NVVanPhong extends NhanVien {
    private double luongCoBan;
    private int ngayCong;

    public NVVanPhong(String maNV, String hoTen, double luongCoBan, int ngayCong) {
        super(maNV, hoTen);
        this.luongCoBan = luongCoBan;
        this.ngayCong = ngayCong;
    }

    @Override
    public double tinhLuong() {
        return luongCoBan * ngayCong / 26.0;
    }
}

// Lớp con 2
class NVSale extends NhanVien {
    private double doanhSo;
    private double hoaHong;

    public NVSale(String maNV, String hoTen, double doanhSo, double hoaHong) {
        super(maNV, hoTen);
        this.doanhSo = doanhSo;
        this.hoaHong = hoaHong;
    }

    @Override
    public double tinhLuong() {
        return doanhSo * hoaHong;
    }
}

// Chương trình chính
public class QuanLyNV {
    public static void main(String[] args) {
        NhanVien[] ds = {
            new NVVanPhong("VP01", "Nguyen Van A", 12000000, 22),
            new NVSale("SL01", "Tran Thi B", 50000000, 0.05),
            new NVVanPhong("VP02", "Le Van C", 10000000, 25)
        };

        for (NhanVien nv : ds) {
            nv.inThongTin();    // đa hình runtime
        }
    }
}

PHẦN BÀI TẬP (4 MỨC ĐỘ)

Bài tập được chia thành 4 mức từ dễ đến khó. Sinh viên nên làm tuần tự từ mức 1 đến mức 4. Mỗi bài đều có lời giải ẩn trong nút "Xem lời giải".

🟢 MỨC 1 – NHẬN BIẾT (Dễ)

Mục tiêu: Ghi nhớ khái niệm lớp, đối tượng, thuộc tính, phương thức, constructor.

Trắc nghiệm

  1. Đối tượng trong Java được tạo bằng từ khóa nào?
    A. create   B. new   C. alloc   D. instanceof
  2. Constructor trong Java có đặc điểm gì?
    A. Có kiểu trả về void
    B. Trùng tên với lớp và không có kiểu trả về
    C. Phải có từ khóa static
    D. Bắt buộc phải có tham số
  3. Từ khóa nào dùng để kế thừa một lớp?
    A. implements   B. inherits   C. extends   D. super
  4. Thuộc tính private có thể truy cập từ đâu?
    A. Mọi nơi   B. Chỉ trong cùng lớp
    C. Trong cùng package   D. Từ lớp con
Xem đáp án
  1. B – new
  2. B – Trùng tên lớp, không có kiểu trả về
  3. C – extends
  4. B – Chỉ trong cùng lớp

Bài tập lập trình

Bài 1.1. Viết lớp HinhChuNhat có hai thuộc tính dai, rong (double), có phương thức dienTich(), chuVi(). Trong main, tạo một đối tượng và in kết quả.

Xem lời giải 
public class HinhChuNhat {
    double dai;
    double rong;

    public double dienTich() {
        return dai * rong;
    }

    public double chuVi() {
        return 2 * (dai + rong);
    }

    public static void main(String[] args) {
        HinhChuNhat h = new HinhChuNhat();
        h.dai = 5;
        h.rong = 3;
        System.out.println("Dien tich: " + h.dienTich());
        System.out.println("Chu vi: " + h.chuVi());
    }
}

Bài 1.2. Viết lớp SinhVien gồm maSV, hoTen, diemTB. Có constructor đầy đủ tham số, có phương thức inThongTin(). Tạo 2 đối tượng và in ra.

Xem lời giải 
public class SinhVien {
    String maSV;
    String hoTen;
    double diemTB;

    public SinhVien(String maSV, String hoTen, double diemTB) {
        this.maSV = maSV;
        this.hoTen = hoTen;
        this.diemTB = diemTB;
    }

    public void inThongTin() {
        System.out.println(maSV + " - " + hoTen + " - " + diemTB);
    }

    public static void main(String[] args) {
        SinhVien sv1 = new SinhVien("SV01", "Nguyen Van A", 8.5);
        SinhVien sv2 = new SinhVien("SV02", "Tran Thi B", 9.0);
        sv1.inThongTin();
        sv2.inThongTin();
    }
}

🟡 MỨC 2 – THÔNG HIỂU (Trung bình)

Mục tiêu: Hiểu đóng gói, getter/setter, nạp chồng, static.

Trắc nghiệm

  1. Để che giấu dữ liệu, ta dùng phạm vi truy cập nào cho thuộc tính?
    A. public   B. protected   C. private   D. Không cần
  2. Phương thức static có thể gọi qua đâu?
    A. Chỉ thông qua đối tượng   B. Qua tên lớp hoặc tên đối tượng
    C. Chỉ qua this   D. Không thể gọi
  3. Đoạn code sau có lỗi gì? 
    public class A {
    private int x;
}
public class B {
    void test() { A a = new A(); a.x = 10; }
}
    A. Không lỗi   B. Lỗi vì x là private
    C. Lỗi vì A không có constructor   D. Lỗi vì B thiếu public
Xem đáp án
  1. C – private
  2. B – Qua tên lớp hoặc đối tượng đều được
  3. B – private không truy cập được từ lớp khác

Bài tập lập trình

Bài 3.2. Viết lớp trừu tượng Hinh có phương thức trừu tượng dienTich() và chuVi(). Tạo các lớp con HinhTron, HinhChuNhat, HinhTamGiac cài đặt hai phương thức đó. Trong main, tính và in thông tin từng hình.

Xem lời giải 
abstract class Hinh {
    public abstract double dienTich();
    public abstract double chuVi();
    public void inThongTin() {
        System.out.printf("%s - DT: %.2f, CV: %.2f%n",
                getClass().getSimpleName(), dienTich(), chuVi());
    }
}

class HinhTron extends Hinh {
    private double r;
    public HinhTron(double r) { this.r = r; }
    public double dienTich() { return Math.PI * r * r; }
    public double chuVi() { return 2 * Math.PI * r; }
}

class HinhChuNhat extends Hinh {
    private double dai, rong;
    public HinhChuNhat(double d, double r) { dai = d; rong = r; }
    public double dienTich() { return dai * rong; }
    public double chuVi() { return 2 * (dai + rong); }
}

class HinhTamGiac extends Hinh {
    private double a, b, c;
    public HinhTamGiac(double a, double b, double c) {
        this.a = a; this.b = b; this.c = c;
    }
    public double dienTich() {
        double p = (a + b + c) / 2;
        return Math.sqrt(p * (p - a) * (p - b) * (p - c));
    }
    public double chuVi() { return a + b + c; }
}

public class Main {
    public static void main(String[] args) {
        Hinh[] ds = {
            new HinhTron(3),
            new HinhChuNhat(4, 5),
            new HinhTamGiac(3, 4, 5)
        };
        for (Hinh h : ds) h.inThongTin();
    }
}

import java.util.Scanner;

abstract class Nguoi {

class SinhVien extends Nguoi {

}

class GiangVien extends Nguoi {

    private String hocVi;

    public GiangVien(String hoTen, int namSinh, String maGV, String hocVi) {
        super(hoTen, namSinh);
        this.maGV = maGV;
        this.hocVi = hocVi;
    }

    @Override
    public String moTa() {
        return "GV " + maGV + ", hoc vi: " + hocVi;

class QuanLy {

Tổng kết chương 5

  • OOP gồm 4 tính chất: Đóng gói, Kế thừa, Đa hình, Trừu tượng.
  • Lớp (class) là khuôn mẫu; đối tượng (object) là một thể hiện cụ thể được tạo bằng new.
  • Constructor trùng tên lớp, không có kiểu trả về; có thể nạp chồng nhiều constructor.
  • Đóng gói: dùng private cho thuộc tính, cung cấp getter/setter kiểm soát truy cập.
  • Kế thừa: dùng extends, gọi constructor lớp cha qua super(...); Java chỉ đơn kế thừa lớp nhưng đa kế thừa interface.
  • Đa hình: Overloading (compile-time) và Overriding (runtime, ghi đè có @Override).
  • Abstract class không tạo được đối tượng, có thể chứa cả phương thức trừu tượng và phương thức thường.
  • Interface là "hợp đồng" hành vi, cho phép đa kế thừa interface.
  • static thuộc về lớp, dùng chung cho mọi đối tượng; final không thể thay đổi/ghi đè/kế thừa.
  • Vận dụng OOP giúp mã dễ đọc, dễ tái sử dụng và mở rộng – đặc biệt quan trọng trong các dự án lớn.
